Apriori Algorithm (Level-Wise Candidate Generation)

R. Agrawal & R. Srikant (1994) • Downward Closure Principle

Step 1: Scan & Count

1-Itemsets ($C_1 \to L_1$)

Counts all 49,688 catalog items. Retains 506 items satisfying min_support ≥ 0.3%.

Step 2: Cross Join

Candidate Gen ($L_{k-1} \times L_{k-1}$)

Generates candidate pairs $C_2$ from frequent 1-itemsets. Prunes pairs with non-frequent subsets.

Step 3: Verification

Support Counting ($L_2, L_3$)

Scans transaction matrix to verify candidate frequencies. 426 pairs and 18 triplets confirmed frequent.

Step 4: Rule Derivation

Confidence & Lift Calculation

Generates rules $X \to Y$. Filters rules with confidence ≥ 15% and lift ≥ 1.0 (346 rules).

Engineering Highlight: 27.1 GiB RAM Explosion Mitigation

When generating candidate itemsets on Instacart's 49,688 products across 131,209 orders, standard MLxtend Apriori attempted to allocate a 3D boolean array of shape (127765, 2, 113705), which triggers an unrecoverable ArrayMemoryError: Unable to allocate 27.1 GiB.

Downward Closure Pre-Filtering: We applied the anti-monotonicity property before matrix conversion, discarding 49,182 non-frequent items and constraining matrix memory to just 54.87 MB.
Low Memory Chunking: Enabled low_memory=True in mlxtend.frequent_patterns.apriori to process candidate pairs iteratively without 3D memory duplication.

FP-Growth Algorithm (Frequent Pattern Tree)

J. Han, J. Pei, & Y. Yin (2000) • Divide-and-Conquer Tree Mining

Architecture Pillar 1

Compact FP-Tree Construction

Scans the transaction database only twice. First scan counts 1-itemset frequencies. Second scan inserts transactions as shared prefix branches into a compact tree.

Architecture Pillar 2

Header Table Item Traversal

Links each frequent item across all branches via pointer chains, allowing O(1) jump access to conditional pattern bases without scanning irrelevant transactions.

Architecture Pillar 3

Candidate-Free Recursive Mining

Recursively constructs conditional FP-Trees for suffix items, mining all 950 frequent itemsets without generating 24.6 million combinatorial candidate pairs.

Execution Efficiency Benchmark

FP-Growth mined all 950 frequent itemsets in 2.829 seconds at 0.3% support, maintaining a strictly bounded memory footprint throughout recursive tree traversal while producing 100% mathematical parity with Apriori.

Algorithm Battle Arena: Apriori vs. FP-Growth

Tested under identical conditions on 131,209 authentic customer transactions across 4 support thresholds.

FP-Growth (Tree-Based Mining)

Compresses transactions into a compact Frequent Pattern Tree (FP-Tree) and mines recursively without generating candidate itemsets.

Apriori (27.1 GiB RAM Mitigation)

Optimized via downward closure universe reduction (reducing matrix to 54.87 MB) and low_memory=True chunking.

100% Mathematical Parity

Both algorithms produce identical frequent itemsets (151 at 1.0%, 255 at 0.7%, 475 at 0.5%, 950 at 0.3%) and association rules.
